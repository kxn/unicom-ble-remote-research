# 数据集：原始报文与无损重组视图

可以直接下载本目录尝试解码，不需要遥控器。已获得设备所有者同意公开这些原始语音相关数据。

## 建议入口

1. 阅读 `derived/summary.json` 和本文件的分片说明。
2. 使用 `derived/*.packets.csv` 对照原始通知。
3. 使用 `derived/*.content48.bin` 尝试解释载荷，**不要先假设每个 48 字节都是音频**。
4. 需要精确启动/停止时序或其他通道时，读完整 `raw/voice-1789484721.jsonl`。

## 原始文件

| 文件 | 内容 |
| --- | --- |
| `raw/remote-session.jsonl` | 早期连接、配对、服务/描述符读取和短按键监听；含多次尝试 |
| `raw/keymap-session.jsonl` | 逐键测试完整采集日志，包含阶段标签 |
| `raw/voice-1789484579.jsonl` | 全部通知订阅的被动基线，FD02 初始化消息以及两次语音按键；该会话被人工中断，日志没有完整结束事件 |
| `raw/voice-1789484721.jsonl` | FA 对照、首次 FB 启动、重复 FB 启动的完整会话；包含最终断开 |

这些文件按原始字节复制保存，未重排事件或删改载荷。`docs/*-evidence.jsonl` 是此前整理的事件视图，原始完整日志以这里的 `raw/` 为准。JSONL 没有 HCI 无线层原始帧，只包含实验脚本记录的 ATT/GATT 应用事件；不能用于分析未记录的链路层重传。

操作指令的秒数是大约值，不是外部标定。通知间隔与真正的编码音频时长是否一一对应尚未验证。

## 二进制派生文件

- `*.att20.bin`：按原始接收顺序直接拼接该实验的 FC ATT values；**每 20 字节一条原始通知**。
- `*.content48.bin`：每组去掉各片前 4 字节，再依分片 0、1、2 拼接；**每 48 字节一组内容**。保留全部未知尾部字节，没有补音频头、没有删填充或猜测编码。
- `*.packets.csv`：每条通知的源日志行号、时间、序号、分片号与完整十六进制。源日志统一为 `raw/voice-1789484721.jsonl`，行号从 1 开始。
- `groups.jsonl`：逐组的三个分片内容、48 字节拼接结果、原始行号及尾部一致性检查结果。

### 已识别与未知字段

原始 20 字节通知：

```text
0..1   小端组序号
2..3   小端分片号，0 / 1 / 2
4..19  16 字节分片内容
```

48 字节拼接内容：

```text
0..31  前两片的内容，业务格式未知
32..39 第三片前八字节，业务格式未知
40..41 小端值 0..29，含义未知
42..43 重复组序号，396/396 匹配
44..47 重复内容偏移 28..31，396/396 匹配
```

38/40 字节有效音频长度都仅是假设；重复字段不代表已证明存在内存越界。编码、采样率、是否存在额外处理均未确定。

## 校验与复现

`manifest.json` 包含原始/派生文件及整理证据的大小和 SHA-256。原始文件在迁移时与采集目录逐字节核对。

```powershell
python scripts/export_dataset.py
```

该命令从完整成功会话重新生成派生视图和校验清单，不调用任何音频解码器。解码尝试请写到 `.local/`，并记录明确参数与听辨结果。
